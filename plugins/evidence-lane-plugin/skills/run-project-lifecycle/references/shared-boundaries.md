# Shared Evidence Lane boundaries

The user's active instructions and existing authorization govern the task.
Use the installed `evidence-lane` MCP dependency, `workflow_catalog` and the
exact current action schemas. Missing actions are unavailable; do not invent a
namespace, substitute a retired route, call a private endpoint or infer success.
Each first-class skill owns its meaningful workflow and may use multiple actions.

The SDK/MCP envelope carries `project_id`, `expected_revision` when relevant,
and the action's `arguments`. The local owner channel can grant native project
administration. A normal selected-project or remote connection cannot grant
itself that capability. Never infer a project or session from a title or CWD.

Windows Studio is a visible read-only observer of its persistent backend and
bounded OS workers. Codex performs administration and work through the API.
The reduced Mac route uses MCP/SDK/skills/hooks without Windows Studio or its
managed toolchain. Tools, dependencies and model assets belong to the shared
installation; catalog membership does not establish installation or readiness.

Every authority and sector owns its SQLite database, schema history and files.
project evidence head coordinator publishes coordinated lane references. Plan, ChatLineage, task exchange authority,
Memory, Learning, Sources, Receipts and Universe remain distinct. Source files,
host instructions and host memory keep their original authority and provenance.

One writer owns a project's work. Follow current Plan contracts, scope, budgets,
required primary/fallback tools and acceptance checks. Handle a stop or semantic
steer at a safe checkpoint, preserve completed history, and reject stale results.
Informational queries do not change Plan. Verified Delta exits record procedural
Learning and bounded Project Memory evidence links atomically with completion.
Do not replay uncertain mutations or effects.

Boot and Resume verify the locked ENV/UOP package and current session head.
ENV/UOP includes current source, workflow, project-class, action, permission,
fallback, verification, disclosure and Plan-projection policies and gates.
Its SQLite, MMD and DOT describe one locked operating framework. Use bounded
`env_uop_inspect` queries when a policy detail matters. The declared policy or
work classification never proves that its action, tool or acceptance check ran.
After attachment read every page of one pinned Plan revision before projecting
the whole native Step Task List when needed. Do not confuse a project Plan read
with native Goal control. Hooks capture only documented visible events; a
reported host session or model label is not independent native attestation.
Use `session_context` for the current bounded Plan window and separate lane
references. Pre/PostCompact seal and pair exact engine-scoped context; only
documented SessionStart and UserPromptSubmit output supplies additional context.
Resolve missing or changed bindings before work. These references never grant
execution or prove native Goal, task or installed-hook continuity.

Preserve actual failures and unsupported fidelity in results.
