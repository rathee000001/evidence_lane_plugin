# Evidence Lane v4

Evidence Lane keeps project work, source evidence and scoped tools together through a persistent engine and visible Studio.

The v4 development target gives each authority and sector lane its own SQLite database and files under the selected external project root. Root PV coordinates their references and published heads. Plan, ChatLineage, Canon, Project Memory, Learning, source provenance and sector profiles retain separate ownership. Each lane keeps the artifact files and toolchain its operations require.

Native MCP clients connect to the engine's typed action registry. An optional HTTPS engine supports separately configured remote project access. Studio remains visible in development and shipping as a read-only observer, with open, minimize and reopen controls. Codex drives project, Plan, work and configuration changes through the plugin.

The Windows package carries a first-detection launcher and complete shared-bundle plan. A release enables that path only after every component archive is SHA-256 bound to one immutable tag in this repository and the exact sparse plugin root is sealed. First detection then materializes one versioned installation under `C:/Apps/EvidenceLaneStudio` (or the explicit `EVIDENCE_LANE_STUDIO_ROOT`), registers its short native Studio launcher, and re-enters MCP through the immutable installed plugin copy. External services remain unconfigured until their own grants are supplied. Ghostscript remains license-gated. No project database or credential belongs in a release component.

This is an uninstalled preinstall candidate with a hash-bound release plan. It is not install-ready until the exact Git ref and release assets are published and read back. Source and protocol tests do not claim an installed plugin, Studio, provider or native operation. Public release documentation follows installed-runtime qualification.
