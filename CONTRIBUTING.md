# Contributing to Evidence Lane

Evidence Lane is privately governed source. An issue, discussion, review,
test result, or suggested direction does not by itself grant source-write
authority or create authorship.

## Before proposing a change

1. Identify the exact problem, affected surface, and current evidence.
2. Keep the proposal bounded to one reviewable Delta.
3. Preserve project, session, source, Plan, and accepted-PV identities.
4. Do not include secrets, private project data, generated caches, or
   unlicensed third-party material.
5. State the evidence that would falsify the proposed correction.

## Review requirements

A source contribution is eligible for acceptance only when it has:

- an attributable author and an explicit rights basis;
- a reviewable Git Delta against the requested branch;
- focused tests plus the required clean CI evidence;
- no inferred HIL, candidate acceptance, pointer movement, release, or
  deployment authority; and
- explicit human acceptance through the governed project lifecycle.

Security vulnerabilities should follow [SECURITY.md](SECURITY.md), not a
public issue. Ownership, reviewers, toolchain credits, and the distinction
between assistance and authorship are recorded in
[Credits and contributions](docs/CREDITS_AND_CONTRIBUTIONS.md).
